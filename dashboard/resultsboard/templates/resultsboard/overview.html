3. Target definition

Binary classification target, computed per company-quarter t:

next_quarter_return = price(end of t+1) / price(end of t) − 1

target = 1 if next_quarter_return > 0, else 0

Prices are the last trading day on/before each quarter end, from the canonical, de-duplicated daily stock series for that company (pipeline/lib/target.py). The final quarter of each company's series is dropped — there is no next-quarter price to compare against yet.

4. Feature set (22 candidates, 18 used)

11 market features + 11 fundamental features, defined in pipeline/lib/features.py. The thesis's original feature dictionary (exact formulas) was not available in this repository, so standard, documented finance formulas are used instead — a stated assumption, not the frozen original specification.

Market features (11)

Historical return over 1/2 quarters and 1 year, 3- and 6-month momentum, 20/50/200-day moving-average ratios, 60- and 120-day volatility, and 60-day volume change.

Fundamental features (11)

Revenue growth, profitability margins (net profit, operating), return on equity/assets, leverage (debt-to-equity), liquidity (current ratio, quick ratio proxy), efficiency (asset turnover), and valuation (price-to-book, price-to-earnings proxy).

Why 4 features are dropped: no source file in the raw data package carries a clean market_cap or total_debt field, so price_to_book, price_to_earnings_proxy, and debt_to_equity are 100% missing across every row. volume_change_60d is likewise always missing because no volume column survived into the cleaned stock series. These 4 all-NaN columns are excluded from model training entirely (median imputation cannot repair a column with zero real observations).

5. Financial-data timing (avoiding look-ahead bias)

A financial observation for period-end date P may only be used to build a feature for an observation dated O if:

  • Quarterly data: O ≥ P + 60 days
  • Annual data: O ≥ P + 120 days
  • Laboratorios Rovi: actual publication date used directly (no fixed lag) — though this company currently contributes zero rows regardless; see Limitations.

Implemented in pipeline/lib/lag.py, enforced when building the feature/target dataset in pipeline/_04_features_target.py.

6. Train / validation / test split

Chronological split by quarter-end — never random — so no future information leaks into training:

  • Train: quarter_end < 2022-01-01
  • Validation: 2022-01-01 ≤ quarter_end < 2024-01-01
  • Test: quarter_end ≥ 2024-01-01

Missing values are imputed using train-set medians only, computed once and applied identically to validation and test, so no validation/test information ever influences imputation. Hyperparameters are scikit-learn defaults, frozen before any test-set evaluation; each model is scored on the held-out test set exactly once.

7. Known data limitations

  • Laboratorios_Rovi has zero daily-price rows in the source archive (no market-data files at all) and contributes no dataset rows.
  • Zenotech_Laboratories has zero financial-statement rows (only unread .xlsx files); its market features still compute, but fundamentals are always missing for this company.
  • market_cap and total_debt have no clean source field anywhere in the raw data, so 3 fundamental ratios and 1 market feature are always missing (see §4).
  • Dataset size and date range (this run: {{ summary.row_count }} rows) differ from the original thesis's reported 1,410 rows / 2014Q3–2026Q1 window, because several companies' real cleaned stock series extend decades earlier than the thesis's assumed 2014 start — confirmed against the real source data, not a defect.
  • The target definition, financial-lag rule, and feature/frequency choices above are the pipeline's own working assumptions (per documentation .pdf's stated defaults), not yet confirmed by the thesis supervisor. See thesis_results/RESULTS.md §7 for the full list of open questions sent for confirmation.
